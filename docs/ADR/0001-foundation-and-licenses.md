# ADR-0001：以 Mo-Shen 为编排参考，自研质量层与记忆层

- 状态：Accepted
- 日期：2026-11-01
- 决策人：项目发起人

## 背景

规划文档提出“四层架构 + 7 Agent 流水线”，并列出 5 个参考仓库。需要决定：

1. 以哪个仓库为底座；
2. 无许可证仓库怎么用；
3. 存储与模型选型；
4. 哪些模块自研。

## 决策

1. **编排参考 Mo-Shen v2.0.2（MIT）**：复用其 AgentScope 2.x 结构、确认关口、`task_id` 后台任务、SSE 与小程序接入思路；保留 MIT 版权声明。
2. **质量层、记忆层、一致性规则全部自研**：按 `SPEC-quality.md`、`SPEC-memory.md` 实现。
3. **无许可证仓库只作需求参考**：
   - `xt-webnovel-writing`：只借鉴“AI 文失效类别”，不复制 25 条条款原文、prompt、代码；
   - `my-novel-agent`：只借鉴“按信息价值分级压缩”的策略，不复制代码、prompt、schema。
4. **存储用 PostgreSQL + JSONB**，M3 前不引入 Neo4j/Milvus/Redis。
5. **默认模型 DeepSeek**，通过配置切换其他 provider。
6. **参考仓库放 `references/`，整目录 gitignore**，不进入自研历史。

## 理由

- Mo-Shen 是唯一同时满足 MIT、AgentScope 2.x、7 Agent、微信小程序、确认关口的现成骨架；
- 质量层和记忆层是产品差异化的核心，且规则/表结构简单，自研可控、无许可风险；
- 无许可证仓库的价值是“问题清单”，不是“代码来源”；独立实现成本低于法律风险；
- PostgreSQL JSONB 足以覆盖角色-事件-时间线查询，Neo4j 是过度设计。

## 后果

正面：

- M1 可快速验证；
- 核心资产（规则、账本、prompt）完全自有；
- 许可边界清晰。

负面：

- 依赖一个 15 stars 的小仓库，需要适配器隔离，必要时替换；
- 质量层校准需要真实样章，周期约 1–2 周；
- 8 条 MVP 规则的效果需要数据验证，不能照搬 25 条。

## 复审触发条件

- Mo-Shen 无法在干净环境部署；
- AgentScope 2.x 依赖不可控；
- 规则误报率 >15% 或平均重写 >2；
- 商用合规要求变化。
