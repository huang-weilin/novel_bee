# 微信小程序（本地版）

小程序只是本地网页之外的另一个入口，不复制生成逻辑：它通过 `wx.request`
调用和网页版相同的 FastAPI 接口。代码在仓库的 `miniprogram/` 目录，**不需要
Node.js、npm 或前端构建**，用微信开发者工具直接打开即可。

> 当前定位是“自己电脑上的写作工具”。没有登录、没有内容安全检查，也没有云端
> 后端。不要把它理解成已经可以上架的小程序。

## 1. 先启动本地后端

在电脑上：

```bash
python -m novel_pipeline.server
```

默认地址是 `http://127.0.0.1:8000`。AI Key 可以在电脑网页右上角的 **AI 设置**
里配置（只写入本机 `.env`），小程序本身不会接触 Key。

如果通过局域网 IP 打开网页，AI 设置接口会返回 `403`；请在本机
`http://127.0.0.1:8000` 配好，或手动编辑电脑上的 `.env`。

## 2. 用微信开发者工具打开

1. 打开微信开发者工具，选择“导入项目”；
2. 目录选仓库里的 `miniprogram/`；
3. AppID 选“测试号/游客模式”即可（`project.config.json` 已填 `touristappid`）；
4. `project.config.json` 已设置 `urlCheck: false`，因此开发者工具可以访问
   `http://127.0.0.1:8000` 这种本地 http 地址；
5. 首页顶部的“后端服务”填 `http://127.0.0.1:8000`，点“保存”，看到“已连接”
   和 AI 模型名后即可使用。

如果首页显示“后端未连接”，先确认后端窗口还在运行，再检查地址有没有多写
路径或端口。

## 3. 真机预览

手机和电脑必须连同一个 Wi-Fi，并且后端要监听局域网地址：

```bash
python -m novel_pipeline.server --host 0.0.0.0
```

然后在小程序首页把后端地址改成电脑的局域网 IP，例如
`http://192.168.1.20:8000`。Windows 防火墙可能拦截 8000 端口，需要允许
Python 的局域网访问。

这条路径只适合在家里/办公室临时调试。`--host 0.0.0.0` 会把没有登录的后端
暴露给同一局域网，用完请改回默认的 `127.0.0.1`。微信正式环境还要求 HTTPS
域名、域名白名单和备案，不能直接用局域网 IP 发布。

## 4. 三个确认关口

### 4.1 大纲确认

在作品页点“写第 N 章”进入。填写本章大纲（必填）、目标字数、视角，按题材
选择性地填场景卡，然后有两个选择：

- **先试写，确认方向**：推荐。只写一个 300–800 字的短片段；
- **跳过试写，直接写全章**：直接进入完整生成和质量门。

### 4.2 试写确认

试写是“真的写一段”，但**不写入记忆、不占用章节**。页面上会显示这段文字，
你可以：

- **按这个方向写全章**：带着这段试写作为方向参考，正式生成整章；
- **换个方向再试**：重新试写一次；
- **返回改大纲**：回到上一页修改设定。

试写片段最多 2000 字会作为方向提示传给正式生成，提示词明确要求“不要照抄
原句”。它不会替代大纲，也不会被直接存成章节。

### 4.3 质量待确认

正式生成后，如果质量门没有直接通过，或者记忆抽取发现缺人物/物品，章节会
显示为“待确认”：

- 正文已经保存，但**记忆还没有写入**；
- 页面会列出待确认原因。人物可以填一句当前状态后“登记人物”，物品可以填
  数量和单位后“登记物品”；
- 登记完点“重写本章”，系统会重新生成、重新检查并尝试写入记忆；
- 只有“定稿”的章节才允许继续写下一章。确认项没处理就往下写，后续章节会
  缺少这一章的记忆。

伏笔、情报、情感债等更复杂的待确认项，目前小程序只展示原因，需要到电脑
网页版或改大纲/正文后重写。

## 5. 任务与导出

生成任务在后台运行，小程序每 1.5 秒查询一次进度，单章最多等 20 分钟。服务
重启会丢掉“进行中”的任务状态，但已经写出的章节正文和记忆都在 SQLite 里，
重新打开作品即可看到。

作品页的“导出全文”会优先把全文复制到剪贴板；文本太长时会改为复制导出
链接，需要在电脑浏览器打开。

## 6. 已知限制

| 限制 | 说明 |
|---|---|
| 无登录 | 本地单用户工具，后端只有回环地址时最安全 |
| 无 `msgSecCheck` | 尚未接微信内容安全接口，不能作为公开产品上线（见 T4-4） |
| 无流式输出 | 微信没有 `EventSource`，小程序仍用 1.5 秒轮询；网页端有 SSE 任务进度，但也不是逐 token 正文流（见 T4-3） |
| 任务不持久 | 后端重启后，进行中的任务丢失，章节不会丢 |
| 单 worker | 同一作品同时只能跑一个任务，换作品也要排队 |
| 游客 AppID | 只适合开发和预览；正式发布需要自己的小程序 AppID 与服务器域名 |

合规与发布不在当前版本范围内。真要做公开产品，至少需要：自有 AppID、HTTPS
域名与备案、登录、`msgSecCheck` 双端检查、AI 生成内容标识，以及多用户隔离
的 PostgreSQL 后端。
