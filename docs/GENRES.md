# 题材分层：一条引擎，多种题材策略

> 这份文档回答：工具怎么支持不同题材，而不为每本书复制一条管线。
> 结论：核心引擎共用；题材只提供“生成策略和自检清单”。新增题材 = 新增一份数据，不改 pipeline、记忆表、一致性规则和质量门。

## 1. 不该做什么

不要按题材复制 `pipeline`、`memory`、`consistency`、`quality` 代码。那样每加一个题材，就要维护一条分叉；一个 bug 要修 N 遍，长篇记忆和一致性会分叉，测试也会失控。

题材不是设定集。人物、门派、物价、世界规则属于项目记忆和大纲，不写进代码；代码里的题材层只回答“这个类型的小说，通常怎么写才成立”。

## 2. 分层

### 共享层（所有题材一致）

- 编排：上下文 → 生成 → 质量/一致性 → 抽取 → 定稿。
- 记忆：L0/L1/L2/L3、角色、物品、信息差、伏笔、情感债、世界规则。
- 一致性：R01–R07。
- 质量门：Q01–Q10、四维评分、`accept/polish/rewrite/human_review`。
- 数据表：不为题材加表；不为题材加状态机分支。

### 题材层（`src/novel_pipeline/genre.py`）

| 字段 | 作用 | 进入哪里 |
|---|---|---|
| `narrative_rules` | 这个题材“怎么写才对”的规则 | 系统提示【题材专项】 |
| `contract_rules` | 本章必须做到的硬要求 | 输出契约 |
| `scene_plan_required` | 本章场景卡必填字段 | `ScenePlan.to_prompt()` + 缺失警告 |
| `quality_notes` | 生成时自检清单 | 系统提示【题材自检】 |
| `extraction_focus` | 抽取时优先关注的类别 | 抽取器 prompt 的“题材关注” |

`scene_plan_required` 只能填 `planning.SCENE_FIELD_LABELS` 里的字段名；未知字段会被忽略。缺项时 `ContextAssembler` 在 `warnings` 里报 `scene plan missing required fields for <key>`，生成仍可继续，场景卡会提示模型自己补全。

## 3. 内置题材

| key | 显示名 | 别名 | 必填场景卡 |
|---|---|---|---|
| `default` | 通用 | 无 | 无 |
| `xianxia_comedy` | 仙侠喜剧 | 修仙喜剧、都市修仙、仙侠现实向、仙界职场 | 开篇钩子、读者赢面、压制、失败代价、兑现工具、兑现、更大问题 |
| `gufeng_mystery` | 古风悬疑 | 古代悬疑、权谋、古风权谋、古代权谋 | 目标、阻碍、代价、转折、兑现、更大问题 |
| `urban_romance` | 都市言情 | 现代言情、甜宠、言情、都市情感 | 情感任务、蓄力、转折、释放、余韵、还债、新债 |

注意：普通“仙侠”故意不映射到 `xianxia_comedy`，避免旧项目行为被悄悄改掉。要启用题材策略，项目 `genre` 写别名之一，或后续在小程序里显式选择。

## 4. 怎么新增题材

1. 在 `genre.py` 增加一个 `GenreProfile`，写 `key`/`label`/`aliases`。
2. 只写这个题材真正不同的规则；通用规则已经在 `DEFAULT_NARRATIVE_RULES` 里，不要复制。
3. `scene_plan_required` 只填 `SCENE_FIELD_LABELS` 中的字段名。
4. 加测试：别名解析、必填字段、context/extractor prompt。
5. 不要为题材加数据库表、状态机分支或质量规则 ID；如果确实需要新的判断，先考虑能否用现有字段 + 题材清单表达。

## 5. 例子：修仙界315

项目 `genre` 用“仙侠喜剧”。生成时：

- 系统提示追加【题材专项】：先给具体的人、制度一本正经地荒诞、主角有私心/恐惧/代价、兑现可以小、反派有真实权力、情感落在物件上。
- 场景卡必填七项；缺项时 `context.warnings` 报 `scene plan missing required fields for xianxia_comedy`。
- 输出契约追加：赢面具体、笑点不解释、选择要付代价。
- 抽取器追加“题材关注：规则与收费、承诺与欠债、关键物件、人物把柄/软肋”。

## 6. 当前边界

- 题材目前只影响生成与抽取的 prompt；质量 Verifier/Scorer 还没有按题材加权（下一阶段）。
- 没有按题材切换规则阈值、记忆表结构或编排分支。
- 别名是精确匹配（忽略大小写和首尾空格），不做模糊分类；识别不了就回退 `default`。
- 题材 profile 不是设定集：人物、门派、物价、规则放项目记忆/大纲，不写进代码。
- 目前只内置三类；新题材应先跑 2–3 章人工试读，再决定是否值得固化成 profile。
