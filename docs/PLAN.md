## 1. 目标

构建一条能稳定产出可读章节的生成管线，先在本机/服务端跑通，再接入微信小程序。

衡量标准只有三个：

1. 跑通一章；
2. 跑通十本；
3. 跑通长篇不崩（角色、物品、伏笔、信息边界不失忆）。

## 2. 核心原则

1. **单管线**：不为“几个 Agent”做产品叙事，只做一条可验证的生成链。
2. **垂直切片**：一次只开一条端到端链路，跑通再加宽。
3. **物理隔离**：`references/` 只读、不提交、不进产品；自研代码只放 `src/`。
4. **许可红线**：MIT / Apache-2.0 可用；无许可证的仓库只借鉴思想，不复制代码、prompt、条款原文。
5. **人工兜底**：质量层不追求 100% 自动，失败时进入“待人工确认”关口。
6. **成本可控**：平均每章重写次数 ≤ 2；超过就砍规则或放宽阈值。

## 3. 范围

### 做

- 设定输入 → 大纲 → 试写确认 → 逐章生成
- 质量层：反 AI 味硬门 + 四维评分 + 重试/人工确认
- 结构化记忆：角色、物品、信息差、伏笔、世界规则
- 长线伏笔调度：重要度、目标回收章、最近推进章、R06 逾期提醒
- 跨章一致性规则校验
- 小程序端确认关口与流式进度（M4）

### 不做（M0–M3）

- 多人协作、计费、运营后台、多租户
- 自训练模型
- Neo4j / Milvus / Redis（初期）
- 全自动无人值守长篇（保留人工确认）
- 25 条反 AI 味规则全量上线（先做 8 条 MVP）

## 4. 架构

```
交互层：确认关口 + 流式进度（M1 用 Mo-Shen H5，M4 接小程序）
────────────────────────────────────────────
编排层：AgentScope 2.x（以 Mo-Shen MIT 版为参考/底座）
────────────────────────────────────────────
生成层：Planning → Writing → Revision
质量层：① 反AI味硬门 ② 四维评分 ③ 跨章一致性
────────────────────────────────────────────
记忆层：结构化事实（PostgreSQL）+ 分级摘要 + 长线伏笔调度，历史正文不进 prompt
```

分层目的：生成层可随模型替换；质量层是稳定工程约束；记忆层控制成本、防止长篇失忆。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| Mo-Shen 仓库小（15 stars），未验证 | M1 可能卡住 | 第一件事跑通；适配器隔离，必要时只复用其确认关口/API 思路 |
| AgentScope 依赖面不清 | 环境装不上 | 独立 venv + 锁版本；记录依赖清单 |
| 规则误杀导致重写成本上升 | 单章成本失控 | 先 8 条；阈值用样章校准；平均重写 > 2 就放宽/砍规则 |
| 记忆抽取错误污染账本 | 长篇越写越错 | 抽取结果带证据；低置信度进人工确认；规则只做阻断不做自动改写 |
| 小程序合规 | 上线受阻 | `msgSecCheck` 双端接入；AI 生成标识；商用前做合规评估 |
| 无许可证仓库的相似性 | 法律风险 | clean-room：以本文档为需求源；不读源码实现；保留设计记录 |

## 10. 工作方式

- 同一时间只允许 **一个** `[>]` 进行中任务。
- 每周做一次“砍范围”：没跑通的模块不并行开发。
- 提交粒度小；`main` 只放可运行版本。
- 文档先行：先改 SPEC，再写代码。
- 不引入 Jira / Notion / 第三方开发流程 skill；一个计划源 + 一个任务清单足够。
