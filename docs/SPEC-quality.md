# 质量层规格 v0.1

> 状态：Draft（待评审） · 更新：2026-11-02
> 对应里程碑：M2。规则枚举与阈值是实现契约，改动需更新本文件。

## 1. 目标

在 Mo-Shen 的 Review Agent 之后，独立判断一章是否可交付，并给出**可执行的修订指令**。

非目标：

- 不替代人做最终审美判断；
- 不做全文润色；
- 不在 M2 做跨章一致性（M3）。

## 2. 输入 / 输出契约

### 输入

```json
{
  "project_id": "uuid",
  "chapter_seq": 1,
  "genre": "仙侠",
  "outline": "本章大纲",
  "character_brief": "主要角色档案摘要",
  "style_constraints": "文风要求/禁忌",
  "target_words": 2000,
  "content": "章节正文"
}
```

### 输出

```json
{
  "pass": false,
  "score": 68,
  "decision": "polish",
  "dimensions": {
    "character": 72,
    "pacing": 65,
    "hook": 70,
    "style": 64
  },
  "failures": [
    {
      "rule_id": "Q04",
      "severity": "major",
      "evidence": "……值得注意的是……（第 3、7、12 段）",
      "suggestion": "删除套话连接词，用动作或场景切换代替"
    }
  ]
}
```

约束：

- `evidence` 必须能在正文中定位，LLM 规则最多引用 80 字；
- `severity` ∈ `blocker | major | minor`；
- `decision` ∈ `accept | polish | rewrite | human_review`；
- 未知字段忽略，缺失必填字段视为本层失败，走人工确认。

## 3. 规则集（当前 12 条）

规则 ID、阈值、判定方式均为本项目自定，不复制参考仓库的条款文本。

### 程序化规则（零 Token，确定性）

| ID | 名称 | 判定 | 严重度 |
|---|---|---|---|
| Q01 | 碎片化排版 | 连续 ≥3 段为单句段，或单句段占全章 >30% | minor |
| Q02 | 段落长度机械均匀 | 段落长度标准差/均值 < 0.25，且段落数 ≥20 | major |
| Q03 | 强调符号过密 | 粗体/斜体标记 >6 处/千字，或小标题 >1 个/500 字 | major |
| Q04 | 套话连接词过密 | 自定义词表命中 >5 次/千字 | major |
| Q05 | 句长分布单一 | 15–35 字句子占比 >75%，或平均句长 <12 字 | minor |
| Q06 | 短语重复 | 4-gram 最高重复 >3 次（排除人名/专名） | minor |
| Q11 | 中文标点/格式 | 汉字紧邻的半角 `, . ! ? ; :`、`...`、`--`，或包住中文的直引号 | major |
| Q12 | 章节长度容差 | 正文字数在目标字数的 70%–130% 之外；只在提供 `target_words` 时检查 | minor |

> 2026-11-01 复核：原《没钱修什么仙？》第 1、2 章免费章节的单句段占比为 66.5% / 60.3%，叙述段里单句段占比 84.1% / 69.3%，读感仍然成立。说明“单句段多”本身不是缺陷，而是对话和动作节拍的正常排版。Q01 因此从 `major` 降为 `minor`，只作提示，不再强制 polish；真正的“碎”要靠场景是否有推进来判断，留待 Q13（因果/场景链）或人工试读。

> 2026-11-02 Q11 编号说明：TASKS 曾把“中文标点/格式”排为 Q11；本文件旧版把 Q11 预留给“因果链像流程图”。为避免实现与任务表冲突，Q11 现指中文标点/格式，原候选顺延为 Q13。Q11 只查紧邻汉字的半角符号，英文术语、数字、代码里的半角标点不误报。Q12 是告警级：篇幅超出容差不会单独把章节打成 polish，仍由分数和 major 规则决定是否修订。

实现要求：

- 词表放配置（`config/quality.json`，用标准库解析，避免引入 PyYAML），不硬编码；
- 每条规则输出 `rule_id / severity / evidence / metrics`；
- 规则引擎必须可单测，输入纯文本、输出纯 JSON。

### LLM 语义规则（Verifier Agent）

| ID | 名称 | 判定 | 严重度 |
|---|---|---|---|
| Q07 | 角色说明书式表达 | 对话/独白在复述设定、解释世界观，而不是推进场景 | blocker |
| Q08 | 总结式收尾 / 情绪直给 | 结尾 2 段总结主题，或直接标注情绪而无行为/感官支撑 | major |
| Q09 | 冗余 / 解释性重复 | 同句多个小句说同一件事，或追加细节删掉后动作/人物/线索都不受影响 | major |
| Q10 | 过度明确 / 留白不足 | 情感/关系/余韵节点把走位、手势、眼神、意图全部写满；删掉一个动作后场景仍成立 | major |

Verifier 契约：

- 输入：正文 + 本章大纲 + 角色摘要；
- 输出：严格 JSON，逐条给 `rule_id / hit / evidence / suggestion`；
- 一次只判断 Q07、Q08、Q09、Q10，不扩项；
- 温度 0.0（2026-11-02 起），减少同一章多次评审的结论漂移；失败重试 1 次，仍失败则标记 `human_review`；
- 宁缺毋滥：只报高置信、真正影响阅读的问题；Q08 最多 2 条、Q09 最多 2 条、Q10 最多 1 条，总量 ≤4 条；
- 明确的“不算”清单：Q08 不报具体动作/对话/悬念收尾和台词里的情绪；Q09 不报对话口癖、有意重复、声口/氛围/节奏/伏笔/动作锚点/空间信息、并列的具体细节和必要因果；Q10 不报叙述者推测、前史、氛围和伏笔。

输出示例：

```json
{"findings": [{"rule_id": "Q07", "hit": true, "evidence": "原文摘录（≤80字）", "suggestion": "把设定改由动作或冲突带出"}]}
```

`hit=false` 的条目忽略；未知 `rule_id` 忽略；`evidence` 缺失视为本次输出无效，重试后转人工。

## 4. 评分与决策

### 四维评分

| 维度 | 权重 | 评分依据 |
|---|---|---|
| 人设一致性 | 30% | 行为是否符合角色档案与当前状态 |
| 节奏 | 25% | 场景推进、信息释放、拖沓/跳跃 |
| 钩子 | 25% | 章末悬念、目标感、下一章牵引 |
| 文风 | 20% | 与项目风格约束的匹配度、语言质量 |

每维 0–100，加权平均为 `score`。

> Q09 只抓“冗余/解释性重复”，不判断画面感、情感蓄力或幽默感。3 章实跑均分 82/84/85、10 章回归均分 83.0，仍不能证明故事好看；高分不能替代人工试读。镜头感与情感节拍目前由 `docs/STYLE.md` 的生成/修订提示和可选场景卡约束，自动规则只覆盖冗余这一小部分。

### 决策优先级

1. 任一 `blocker` → `rewrite`（不论分数）；
2. `score < 55` → `rewrite`；
3. `55 ≤ score < 75` → `polish`；
4. `score ≥ 75`、无 blocker、无 major → `accept`；
5. `score ≥ 75` 但存在 major → `polish`（反 AI 味硬门：高分不能直接放过 major）；
6. 重试达到上限 → `human_review`。

> 2026-11-01 校准调整：原规则允许 major 在 `score ≥ 75` 时直接 accept，实测会让 Q01 等 major 问题被高分掩盖；现收紧为至少 polish。

### 重试上限

| 动作 | 上限 | 说明 |
|---|---|---|
| rewrite | 3 次/章 | 比参考方案的 5 次更保守，控成本 |
| polish | 2 次/章 | 只注入失败项，不重写全章 |

成本护栏：滚动统计最近 10 章平均重写次数，>2 时告警并进入阈值复核，不自动加规则。

## 5. 与 Mo-Shen Review Agent 的关系

- Mo-Shen 的 Review 保留，作为第一道评审；
- 本层 Scorer 是第二道独立评分；
- 两者分差 >20 分时，不自动判定，转 `human_review`；
- 不修改 Mo-Shen 源码；通过适配器接管章节输出。

## 6. 校准与验收

### 校准集

- 10 章人工写作样章 + 10 章 AI 生成样章；
- 每章人工标注“是否存在该类问题”；
- 按规则统计 precision / recall。

### 目标（MVP）

| 指标 | 目标 |
|---|---|
| blocker 规则 precision | ≥ 0.80 |
| blocker 规则 recall | ≥ 0.60 |
| 整体误报率 | < 10% |
| 10 章平均重写次数 | ≤ 2 |
| 评分分布 | 正常章节多数落在 60–90 |

未达标时：先调阈值/词表，仍不达标才考虑换规则；不靠增加规则数量解决。
